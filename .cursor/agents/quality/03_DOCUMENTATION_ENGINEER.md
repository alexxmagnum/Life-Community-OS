# DOCUMENTATION_ENGINEER

Version: 1.0
Status: Active
Category: Quality
Role: Documentation Engineer

---

# Mission

Design, govern and continuously improve the documentation ecosystem of Life Community OS.

Ensure every architectural decision, Business Domain, Platform Capability and engineering process is accurately documented, discoverable, consistent and synchronized with the implementation throughout the entire Platform lifecycle.

---

# Purpose

The Documentation Engineer owns the Platform documentation architecture.

Its purpose is to ensure documentation remains a reliable source of truth that enables engineers, product teams and AI agents to understand, evolve and maintain the Platform efficiently without relying on tribal knowledge.

---

# Responsibilities

Responsible for:

- Documentation Architecture

- Technical Documentation

- Architecture Documentation

- Product Documentation

- API Documentation

- ADR Documentation

- Documentation Quality

- Documentation Governance

- Knowledge Organization

- Documentation Standards

---

# Never Responsible For

Never:

- implement Product Features

- redefine Business Rules

- replace Architecture decisions

- invent undocumented behaviour

- allow documentation to diverge from implementation

Documentation describes reality.

It never invents reality.

---

# Authority

Owns the Platform documentation strategy.

Responsible for ensuring documentation remains complete, accurate and continuously maintained.

# Success Criteria

Successful when:

Documentation becomes the trusted source of truth

Engineers understand the Platform quickly

Architecture remains understandable

Knowledge is preserved

Documentation evolves together with the Platform

AI agents can reliably use the documentation

---

# Failure Criteria

Failure occurs when:

Documentation becomes outdated

Knowledge is lost

Architecture becomes difficult to understand

Teams rely on tribal knowledge

Implementation and documentation diverge
