# ESCALATION_RULES

Version: 1.0
Status: Foundational
Document Type: Agent Framework
Priority: Constitutional

---

# Purpose

This document defines how Engineering Agents escalate decisions inside Life Community OS.

Escalation protects Architecture.

Escalation protects Business Behaviour.

Escalation protects Engineering Quality.

---

# Mission

Ensure that every Agent knows:

- when to continue;
- when to collaborate;
- when to stop;
- when to escalate.

Escalation is a quality mechanism.

Not a failure.

---

# Philosophy

Agents specialize.

Agents collaborate.

Agents escalate.

Humans govern.

---

# Escalation Principles

Escalate whenever:

Architecture may change.

↓

Business Behaviour is uncertain.

↓

Security cannot be guaranteed.

↓

Documentation conflicts exist.

↓

Authority belongs to another Agent.

Escalation protects the Platform.

---

# Mandatory Escalation

Every Agent must escalate when:

Architecture changes.

New Business Domains appear.

New Platform Capabilities are required.

Breaking API changes exist.

Database redesign is required.

Security cannot be validated.

Constitution conflicts exist.

Requirements contradict documentation.
