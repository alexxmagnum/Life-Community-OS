# ENGINEERING_RULES

Version: 1.0
Status: Foundational
Document Type: Agent Framework
Priority: Constitutional

---

# Purpose

This document defines the universal engineering rules followed by every Agent inside Life Community OS.

These rules guarantee that every Agent produces consistent, maintainable and architecture-compliant results.

Engineering remains predictable.

Architecture remains protected.

---

# Mission

Provide a common engineering standard shared by every Agent regardless of specialization.

Every Agent follows the same engineering discipline.

---

# Engineering Philosophy

Architecture first.

Business second.

Implementation third.

Technology fourth.

Never reverse this order.

---

# Universal Rules

Every Agent must:

Understand before implementing.

Read before writing.

Reuse before creating.

Validate before delivering.

Document before finishing.

---

# Architecture Rules

Always respect:

Architecture Constitution

Platform Architecture

Business Domains

Platform Capabilities

Engineering Handbook

Architecture is never optional.

---

# Business Rules

Business Behaviour belongs exclusively to Business Domains.

Business Rules never belong inside:

User Interface

Infrastructure

Automation

Database

Platform Capabilities

---

# Capability Rules

Always verify:

Does a Capability already exist?

Can it be reused?

Can it be extended?

Can it be composed?

New Capabilities are the last option.

---

# Dependency Rules

Dependencies must be:

Explicit

Minimal

Replaceable

Documented

Circular dependencies are prohibited.

---

# API Rules

Every API must include:

Validation

Authentication

Authorization

Versioning

Documentation

Observability

Stable contracts are mandatory.

---

# Database Rules

Every persistence change requires:

Migration

Constraints

Indexes

Repositories

Rollback Strategy

Documentation

Business data remains authoritative.

---

# User Interface Rules

Interfaces should:

Consume Capabilities

Remain Responsive

Remain Accessible

Remain Consistent

Handle Errors

Handle Loading

Handle Empty States

UI never owns Business Behaviour.

---

# Automation Rules

Automation must:

Remain deterministic

Be observable

Support retries

Support rollback

Respect permissions

Automation orchestrates.

Automation never owns Business Behaviour.

---

# Artificial Intelligence Rules

AI implementations require:

Provider Independence

Prompt Versioning

Knowledge Sources

Evaluation

Safety

Cost Awareness

Documentation

AI remains governed.

---

# Security Rules

Always validate:

Authentication

Authorization

Permissions

Tenant Isolation

Privacy

Audit

Encryption

Security is mandatory.

---

# Testing Rules

Every implementation should include:

Unit Tests

Integration Tests

Contract Tests

Regression Tests

Performance Tests when required

Testing is part of engineering.

---

# Observability Rules

Every implementation exposes:

Logs

Metrics

Tracing

Health Checks

Alerts

Nothing remains invisible.

---

# Documentation Rules

Every implementation updates:

Architecture

README

ADR References

Examples

Operational Notes

Documentation evolves together with implementation.

---

# Naming Rules

Always use official terminology from:

PLATFORM_GLOSSARY.md

No alternative terminology is allowed.

---

# Quality Rules

Generated work must be:

Correct

Readable

Reusable

Observable

Secure

Testable

Replaceable

Documented

Quality remains measurable.

---

# Forbidden Behaviour

Agents must never:

Invent Architecture

Invent Business Rules

Duplicate Capabilities

Duplicate Business Behaviour

Ignore Documentation

Ignore ADRs

Break Public Contracts

Hardcode Permissions

Hardcode Tenants

Ignore Security
